# Локальные проверки нотч-плеера

Локальный инструмент разработчика, в PR не входит.

## structural.test.mjs — структурные автотесты (без запуска приложения)

```
node tests/notch/structural.test.mjs
```

Ловит класс регрессий «вставка в минифицированные webpack-чанки»:

- синтаксис тронутых файлов (`node --check`);
- наличие api-поверхности кражи меню в `pulsesync.js`;
- все настройки нотча в чанке настроек живут в **одном** скоупе компонента
  (mobx `PA`) — иначе terser после минификации роняет модалку свободными именами
  (`ReferenceError`, «Something went wrong»);
- terser-контроль с `mangle: true`: свободные имена переживают минификацию;
- darwin-гейты (кнопка в тайтл-баре, блок действий в main);
- отсутствие следов старых li в «Поведении окна».

## e2e.mjs — интерфейсные проверки через CDP

Требует запущенное приложение с дебаг-портом:

```
env -i /usr/bin/open -a "Яндекс Музыка" --args --remote-debugging-port=9222
node tests/notch/e2e.mjs
```

Проверяет как руками: окно нотча, шапка (ссылки/эквалайзер/18+), транспорт,
краденое меню (пункты + иконки + сабменю с мгновенным открытием), Track details
через нотч, ссылка-название → `/album/track?…` с панелью трека (и что панель
не закрывается сама), настройки в «Миниплеере».
